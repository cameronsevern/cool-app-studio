# Support

Cool App Studio is an early open-source project maintained on a best-effort
basis.

## Where to ask

- Reproducible defects: use the bug issue form with synthetic assets.
- Focused product proposals: use the feature request form and connect the request
  to a user outcome.
- Changed App Store or Google Play requirements: use the store-target form and
  include first-party documentation.
- Usage questions: use GitHub Discussions after it is enabled for the public
  repository.
- Vulnerabilities or suspected private-data exposure: follow `SECURITY.md`; do
  not use a public issue.

## What to include

Include the Cool App Studio version or commit, operating system, Node and
browser versions, exact steps or CLI flags, expected result, and sanitized
output. Prefer the included sample assets or a minimal synthetic project.

Do not upload confidential screenshots, portable projects, fonts, credentials,
or proprietary brand assets merely to obtain support.

## Support window

Before `1.0`, support focuses on `main` and the latest public minor release.
Older project files should migrate forward, but pre-release interfaces and
rendering details may change with clear release notes. A longer compatibility
and security-support policy is a `1.0` roadmap gate.
